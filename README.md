## Запуск на macOS

Требуется Python 3.10+ с Tkinter. На этом Mac используйте `python3.12`.
Сборка и дополнительные пакеты для запуска не требуются.
Откройте настоящий терминал и перейдите в папку проекта:

```sh
cd "/Users/alex/Desktop/Учеба/Конфиг/practice-1-variant-17"
PYTHON=python3.12 ./run.sh
```

Если проект находится в другом месте, замените путь в `cd`.
`PYTHON=python3.12` поддерживается с первого этапа и передаётся всем `.sh`.
Без переменной запускается `python3`; у его версии на этом Mac нет Tkinter.
Прямой запуск без скрипта:

```sh
python3.12 -m src.main
```

Команды запуска и тестов вводятся в настоящем терминале Mac. Команды
эмулятора вводятся в нижнюю строку его окна, по одной, с нажатием Enter.
Пока окно открыто, запускающий терминал занят программой. Закройте окно
или введите в нём `exit`, прежде чем запускать следующий сценарий.

## Ключи ls: -l, -a, -h

В нижней строке эмулятора:

```text
ls /
ls -l /
ls -a /
ls -h /
ls -lah /
ls -l -a -h /
ls -lh /large.txt
```

- `-l`: подробный вывод с типом и правами, числом ссылок, владельцем,
  группой, размером, временем изменения и именем.
- `-a`: показать скрытые имена, а также `.` и `..`.
- `-h`: вместе с `-l` показать размеры в единицах K/M/G с основанием 1024.
  Сам по себе `ls -h` выводит обычный список имён.

Ключи можно объединять (`-lah`), передавать отдельно (`-l -a -h`)
и задавать после пути. `--` завершает разбор ключей, например
`ls -- -filename`. Неизвестный ключ вызывает сообщение об ошибке.
Обычный `ls` скрывает имена, начинающиеся с точки; явный путь к скрытому
файлу выводится и без `-a`.

В демонстрационной VFS корня есть `.hidden.txt` и `large.txt` размером
1536 байт. `ls -l /large.txt` показывает 1536, `ls -lh /large.txt` 1.5K.

XML не содержит настоящих прав и владельцев ОС. Эмулятор показывает
виртуальные значения: права каталогов 755, файлов 644, владелец и группа
`vfs`. Размер каталога 0, число ссылок каталога 2 плюс число вложенных
каталогов, файла 1. Время берётся из `Node.modified_at`, первоначально
это момент загрузки/создания объекта, отображение в UTC.
Реальные файлы и права Mac эта команда не читает и не меняет.

Назначение ключей описано в [документации GNU ls][ls-options].

[ls-options]: https://www.gnu.org/software/coreutils/manual/html_node/What-information-is-listed.html

## Команды окна

| Команда | Действие |
| --- | --- |
| `ls [-lah] [путь ...]` | Показать содержимое каталога или имя файла. |
| `cd [путь]` | Перейти в каталог; без пути перейти в корень. |
| `wc [-lwc] файл ...` | Посчитать строки, слова и байты. |
| `tree [путь]` | Показать дерево и итоговое число объектов. |
| `exit` | Закрыть окно и остановить сценарий. |

В нижнее поле окна вводите по одной команде:

```text
cd /home/student/projects
ls
wc hello.txt
wc -l hello.txt
wc -w hello.txt
wc -c hello.txt
tree .
cd ..
ls "todo list.txt"
```

Для `hello.txt` ответ `2 4 49 hello.txt`: 2 строки, 4 слова, 49 байт.
Корень VFS обозначается `/`, текущая папка `.`, родительская `..`.
Пути могут быть абсолютными и относительными. Имена с пробелами заключайте
в кавычки. Команды работают с XML, загруженным в память; XML не изменяется.
Без параметров используется `vfs/deep.xml`. Можно явно выбрать XML
через `--vfs` и стартовый сценарий через `--startup`.

`touch` пока не реализован: он появится на пятом этапе.

## Автоматические тесты

Из корня проекта:

```sh
python3.12 -m unittest discover -s tests -v
```

Для этой версии ожидается 37 тестов и итог `OK`.
Тесты выполняются без создания окна. Они проверяют поведение,

## Проверка оформления

Один раз подготовьте отдельное окружение для инструментов проверки:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
```

Запуск проверки оформления и тестов:

```sh
.venv/bin/python scripts/check_quality.py &&
.venv/bin/python -m unittest discover -s tests -v &&
sh -n run.sh &&
(for script in scripts/*.sh; do
  [ -f "$script" ] || continue
  sh -n "$script" || exit 1
done)
```

Radon и Ruff нужны лишь для проверки, не для запуска эмулятора.
Проверяются применимые правила задания: структура, история коммитов,
отсутствие служебных и двоичных файлов, длина строк и функций, число
аргументов, docstrings, сложность, имена и литералы в сравнениях.
GitHub Actions выполняет проверку оформления, тесты и синтаксис `.sh`.

## Переход к ветке этапа и возврат

Открытие ветки на GitHub не переключает локальные файлы.
Перед переключением убедитесь, что `git status --short` не выводит
изменённых файлов. Для этапа 4 выполните в настоящем терминале:

```sh
git fetch origin
git switch stage-4
python3.12 -m unittest discover -s tests -v
```

Если локальной ветки ещё нет, Git создаст её из `origin/stage-4`.
После демонстрации вернитесь к полной версии:

```sh
git switch main
```
