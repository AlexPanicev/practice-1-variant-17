# Эмулятор командной строки UNIX

Практическая работа №1 по дисциплине «Конфигурационное управление»,
вариант 17. Программа имитирует командную строку UNIX в графическом окне.
Заголовок содержит настоящее имя пользователя и компьютера. Команды
работают с виртуальной файловой системой (VFS), загружаемой из XML.

Полная работа со всеми исправлениями находится в ветках `main` и `stage-5`.
В истории ровно пять коммитов, по одному на этап. Их снимки уже
включают проверенные исправления. При пересборке истории
сохранены исходные даты разработки этапов.

## Подготовка на macOS

Требуется Python 3.10+ с Tkinter. На текущем Mac рабочий интерпретатор:
`python3.12`. Сборка и дополнительные пакеты для запуска не нужны.

Откройте приложение «Терминал» и перейдите в папку проекта:

```sh
cd "/Users/alex/Desktop/Учеба/Конфиг/practice-1-variant-17"
```

Если проект находится в другом месте, замените путь в `cd`.
Все команды запуска и тестирования ниже вводятся в настоящем терминале,
из корня проекта. Команды `ls`, `cd`, `wc`, `tree`, `touch`, `exit` для
демонстрации вводятся в нижнюю строку открывшегося окна эмулятора.

Рабочий запуск на этом Mac:

```sh
PYTHON=python3.12 ./run.sh
```

`PYTHON=python3.12` выбирает Python для одного запуска. Переменная передаётся
также вложенным скриптам. Без неё `run.sh` использует `python3`.
Если появляется `No module named '_tkinter'`, выберите интерпретатор,
в котором установлен Tkinter. Сам переход в папку через `cd` это не меняет.

Справка о параметрах запуска:

```sh
PYTHON=python3.12 ./run.sh --help
```

Эта команда выводит справку в настоящий терминал, не открывая окно.

## Запуск по этапам в main

Следующие сценарии показывают возможности этапов в готовой версии `main`.
Они не переключают файлы на старые коммиты. Для запуска тестов отдельной версии
используйте раздел «Переключение между этапами» ниже.

Запускайте сценарии по одному. Пока окно открыто, терминал ожидает
завершения программы. Перед следующим запуском закройте окно крестиком
или введите `exit` в нижней строке эмулятора и нажмите Enter.

### Этап 1: окно, ввод команд, кавычки и ошибки

Отдельного файла `scripts/01-*.sh` нет. Запуск для ручной демонстрации:

```sh
PYTHON=python3.12 ./run.sh
```

В нижней строке окна вводите по одной команде, нажимая Enter:

```text
ls
cd /home/student
ls "todo list.txt"
unknown
ls "
exit
```

Покажите заголовок окна, историю ввода и ответов, имя с пробелами,
неизвестную команду, незакрытую кавычку и завершение через `exit`.
В готовой версии `ls` и `cd` работают с VFS. В первом этапе они являются
заглушками, которые только показывали разобранные аргументы.

### Этап 2: параметры запуска и стартовый сценарий

Без параметров:

```sh
PYTHON=python3.12 ./scripts/02-no-args.sh
```

Используется `vfs/deep.xml`, стартовый сценарий не задан.
Закройте окно, затем запустите сценарий со всеми параметрами:

```sh
PYTHON=python3.12 ./scripts/02-all-args.sh
```

Эквивалентная команда для ручного выбора параметров:

```sh
PYTHON=python3.12 ./run.sh \
  --vfs vfs/minimal.xml \
  --startup scripts/02-startup.txt
```

`--vfs` выбирает XML с виртуальными файлами, `--startup` выбирает текстовый
файл с командами. В окне отображаются параметры, ввод и ответы сценария.
Пустые строки и комментарии с `#` пропускаются. Комментарий после команды
игнорируется, а `#` внутри кавычек остаётся частью аргумента.

Ошибки в `02-startup.txt` предусмотрены специально: указан отсутствующий
объект, отсутствующая в минимальной VFS папка `/tmp`, команда `unknown`
и незакрытая кавычка. После этих ошибок сценарий продолжает работу.

### Этап 3: XML и разные файловые системы

Минимальная структура с пустой папкой `empty`:

```sh
PYTHON=python3.12 ./scripts/03-minimal.sh
```

Несколько файлов, текстовые и двоичные данные:

```sh
PYTHON=python3.12 ./scripts/03-files.sh
```

Вложенная структура папок:

```sh
PYTHON=python3.12 ./scripts/03-deep.sh
```

Отдельная проверка завершения сеанса:

```sh
PYTHON=python3.12 ./scripts/03-exit.sh
```

Последний сценарий автоматически закрывает окно командой `exit`.
Это ожидаемый результат. Остальные сценарии оставляют окно открытым.

Все операции с VFS выполняются в памяти. XML не изменяется.
Источник имеет корень `<vfs>`, каталоги `<directory name="...">`
и файлы `<file name="...">`. По умолчанию содержимое файлов кодируется
в UTF-8. Двоичные данные хранятся с атрибутом `encoding="base64"`.
Сообщения об отсутствующих путях в сценариях проверяют обработку ошибок.

### Этап 4: ls, cd, wc и tree

```sh
PYTHON=python3.12 ./scripts/04-demo.sh
```

Показывает `ls -lah`, навигацию, режимы `wc` и `tree`, относительные
и абсолютные пути, имена с пробелами и ошибки аргументов.

### Этап 5: touch и полная демонстрация

```sh
PYTHON=python3.12 ./scripts/05-demo.sh
```

Полная демонстрация: основные команды, создание пустых файлов,
обновление времени существующих объектов, несколько аргументов и ошибки.
После завершения можно продолжать ручной ввод в том же окне.

## Все демонстрации подряд

Из корня проекта выполните в настоящем терминале:

```sh
for script in run.sh scripts/*.sh; do
  PYTHON=python3.12 "./$script" || break
done
```

Сценарии выполняются последовательно. После каждого обычного запуска
посмотрите результат и закройте окно, чтобы начался следующий.
`03-exit.sh` закрывается самостоятельно. Это демонстрации с окнами;
автоматические тесты ниже проверяют результаты без ручного просмотра.

## Автоматические проверки

### Все функциональные тесты одной командой

```sh
python3.12 -m unittest discover -s tests -v
```

`-m unittest` запускает встроенный инструмент тестирования, `discover`
находит тесты, `-s tests` задаёт папку поиска, `-v` показывает каждый результат.
Текущая версия содержит 40 тестов. Успешный итог:

```text
Ran 40 tests ...
OK
```

### Отдельный файл тестов

Команды оболочки, включая `wc` и `touch` (13 тестов):

```sh
python3.12 -m unittest discover -s tests -p test_shell.py -v
```

Загрузка XML, содержимое файлов, пути и ошибки VFS (11 тестов):

```sh
python3.12 -m unittest discover -s tests -p test_vfs.py -v
```

Комментарии, ошибки чтения и остановка сценария после `exit` (4 теста):

```sh
python3.12 -m unittest discover -s tests -p test_startup.py -v
```

`-p` выбирает имя файла. Эти команды проверяют текущую версию файлов,
а не автоматически выбирают исторический этап разработки.

Ключи `ls`, метаданные, скрытые файлы и формат размеров (12 тестов):

```sh
python3.12 -m unittest discover -s tests -p test_listing.py -v
```

### Одна конкретная проверка

Например, только `test_wc` из `test_shell.py`:

```sh
PYTHONPATH=tests python3.12 -m unittest test_shell.ShellTests.test_wc -v
```

Полное имя выбирает строго один тест. Чтобы запустить группу проверок,
в имени которых есть `test_wc`, используйте:

```sh
python3.12 -m unittest discover -s tests -p test_shell.py -k test_wc -v
```

`-k` отбирает тесты по подстроке в имени. Эта команда запускает три теста:
`test_wc`, `test_wc_modes_and_totals` и `test_wc_invalid_arguments`.

### Подготовка инструментов проверки оформления

Выполните один раз из корня проекта:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
```

`.venv` является отдельным окружением. Radon и Ruff нужны лишь для проверки
оформления, не для работы эмулятора. Окружение не включается в Git.

### Оформление, тесты и синтаксис скриптов вместе

После подготовки `.venv`:

```sh
.venv/bin/python scripts/check_quality.py &&
.venv/bin/python -m unittest discover -s tests -v &&
sh -n run.sh &&
(for script in scripts/*.sh; do sh -n "$script" || exit 1; done)
```

`&&` запускает следующую проверку только после успешной предыдущей.
Последняя проверка выполняется в отдельной оболочке, поэтому ошибка
скрипта не закрывает основной терминал. `sh -n` проверяет синтаксис,
не открывая окна. При успехе синтаксической проверки отдельного вывода нет.

`check_quality.py` проверяет применимые правила задания (страницы 5-7):
структуру, историю коммитов, отсутствие бинарных и служебных файлов,
длину файлов и строк, функций и списков аргументов, docstring, сложность
до 10, числовые литералы в сравнениях и имена PEP8.

Те же проверки и тесты запускаются в GitHub Actions после каждого push.
Автоматические тесты не заменяют ручную демонстрацию графического окна.

## Ключи ls: -l, -a, -h

В нижней строке эмулятора:

```text
ls /
ls -l /
ls -a /
ls -h /
ls -lah /
ls -l -a -h /
ls -lh /large.txt
```

- `-l`: подробный вывод с типом и правами, числом ссылок, владельцем,
  группой, размером, временем изменения и именем.
- `-a`: показать скрытые имена, а также `.` и `..`.
- `-h`: вместе с `-l` показать размеры в единицах K/M/G с основанием 1024.
  Сам по себе `ls -h` выводит обычный список имён.

Ключи можно объединять (`-lah`), передавать отдельно (`-l -a -h`)
и задавать после пути. `--` завершает разбор ключей, например
`ls -- -filename`. Неизвестный ключ вызывает сообщение об ошибке.
Обычный `ls` скрывает имена, начинающиеся с точки; явный путь к скрытому
файлу выводится и без `-a`.

В демонстрационной VFS корня есть `.hidden.txt` и `large.txt` размером
1536 байт. `ls -l /large.txt` показывает 1536, `ls -lh /large.txt` 1.5K.

XML не содержит настоящих прав и владельцев ОС. Эмулятор показывает
виртуальные значения: права каталогов 755, файлов 644, владелец и группа
`vfs`. Размер каталога 0, число ссылок каталога 2 плюс число вложенных
каталогов, файла 1. Время берётся из `Node.modified_at`, первоначально
это момент загрузки/создания объекта, отображение в UTC.
Реальные файлы и права Mac эта команда не читает и не меняет.

Назначение ключей описано в [документации GNU ls][ls-options].

[ls-options]: https://www.gnu.org/software/coreutils/manual/html_node/What-information-is-listed.html

## Команды внутри эмулятора

Вводите их в нижнюю строку окна, по одной команде, нажимая Enter.

| Команда | Действие |
| --- | --- |
| `ls` | Показать текущую папку. |
| `ls /home/student` | Показать указанную папку. |
| `ls /tmp /home` | Показать несколько объектов. |
| `ls -lah /` | Подробно показать все имена с удобными размерами. |
| `cd /home/student/projects` | Перейти в указанную папку. |
| `cd ..` | Перейти на одну папку выше. |
| `cd /` или `cd` | Перейти в корень VFS. |
| `wc hello.txt` | Посчитать строки, слова и байты. |
| `wc -l hello.txt` | Посчитать только строки. |
| `wc -w hello.txt` | Посчитать только слова. |
| `wc -c hello.txt` | Посчитать только байты. |
| `wc -lw hello.txt` | Посчитать строки и слова. |
| `wc hello.txt hello.txt` | Посчитать несколько файлов и общий итог. |
| `tree` или `tree .` | Показать дерево текущей папки. |
| `tree /` | Показать всё дерево VFS. |
| `touch "new file.txt"` | Создать файл или обновить время объекта. |
| `touch first.txt second.txt` | Создать несколько пустых файлов. |
| `exit` | Закрыть окно. |

`/` означает корень VFS, `.` текущую папку, `..` родительскую папку.
Имя с пробелами заключайте в кавычки. Абсолютный путь начинается с `/`,
относительный отсчитывается от текущей папки.

### Ручная демонстрация основных возможностей

Запустите `PYTHON=python3.12 ./run.sh`. В окне выполните:

```text
cd /home/student/projects
ls
wc hello.txt
touch "new file.txt"
ls
wc "new file.txt"
tree .
```

`wc hello.txt` даёт `2 4 49 hello.txt`: 2 строки, 4 слова и 49 байт.
Для нового пустого файла результат `0 0 0 new file.txt`.
Байты не равны числу символов: буквы кириллицы в UTF-8 занимают несколько
байт. `touch` обычно не выводит ответ; результат виден через `ls` и `tree`.

Все изменения VFS существуют только в памяти текущего сеанса.
При закрытии окна созданные файлы исчезают, исходный XML не изменяется.
Виртуальный путь `/home/student` не является реальной папкой вашего Mac.

### Ошибки, которые можно показать преподавателю

```text
ls /missing
cd /home/student/projects/hello.txt
wc /home
unknown
ls "
```

Это соответственно отсутствующий путь, попытка перейти в файл,
попытка посчитать содержимое каталога, неизвестная команда и незакрытая
кавычка. Сообщения об ошибках здесь ожидаемы. `help` внутри эмулятора
не реализован; справка о параметрах доступна через `./run.sh --help`.

## Структура проекта

```text
README.md               описание и команды для защиты
run.sh                  запуск программы
src/main.py             графическое окно и выполнение сценариев
src/config.py           параметры --vfs и --startup
src/shell.py            разбор и выполнение команд
src/listing.py          ls -l/-a/-h и виртуальные метаданные
src/vfs.py              загрузка XML и виртуальное дерево
vfs/                    XML с учебными файлами и папками
scripts/*.sh            сценарии запуска для настоящей ОС
scripts/*-startup.txt    команды для автоматического ввода в эмулятор
scripts/03-exit.txt      сценарий завершения сеанса
scripts/check_quality.py  проверка правил оформления
requirements-dev.txt    зависимости только для проверки
tests/                  автоматические тесты
.gitignore              исключения Git, включая .venv и кэш Python
.github/workflows/quality.yml  автоматические проверки GitHub
```

`.sh` запускает настоящая оболочка Mac. `.txt` читает эмулятор и выполняет
записанные там команды. Папка `.git` хранит историю локального репозитория;
GitHub хранит опубликованную копию. Пять этапов разработки видны в истории
коммитов, проверенные исправления включены в снимки соответствующих этапов.
