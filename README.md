Практическая работа №1, вариант 17, «Конфигурационное управление».
Графическое окно, история диалога, разбор кавычек и команда exit.

Снимки этапов включают проверенные исправления. При пересборке истории
сохранены исходные даты разработки этапов. Готовая полная работа находится
в ветке `main`; эта версия показывает возможности этапа 1.

## Запуск на macOS

Требуется Python 3.10+ с Tkinter. На этом Mac используйте `python3.12`.
Сборка и дополнительные пакеты для запуска не требуются.
Откройте настоящий терминал и перейдите в папку проекта:

```sh
cd "/Users/alex/Desktop/Учеба/Конфиг/practice-1-variant-17"
PYTHON=python3.12 ./run.sh
```

Если проект находится в другом месте, замените путь в `cd`.
`PYTHON=python3.12` поддерживается с первого этапа и передаётся всем `.sh`.
Без переменной запускается `python3`; у его версии на этом Mac нет Tkinter.
Прямой запуск без скрипта:

```sh
python3.12 -m src.main
```

Команды запуска и тестов вводятся в настоящем терминале Mac. Команды
эмулятора вводятся в нижнюю строку его окна, по одной, с нажатием Enter.
Пока окно открыто, запускающий терминал занят программой. Закройте окно
или введите в нём `exit`, прежде чем запускать следующий сценарий.

## Ручная демонстрация первого этапа

Отдельного сценария `scripts/01-*.sh` нет: запуск выполняется через run.sh.
В нижнюю строку окна вводите по одной команде, нажимая Enter:

```text
ls "two words"
cd /tmp
unknown
ls "
exit
```

`ls` и `cd` пока являются заглушками: показывают имя команды и аргументы.
Например, ответ на `ls "two words"`: `ls: аргументы = ['two words']`.
`unknown` и незакрытая кавычка вызывают ожидаемые сообщения об ошибке.
`exit` закрывает окно. VFS, настройки запуска и чтение сценариев появятся
на следующих этапах.

## Автоматические тесты

Из корня проекта:

```sh
python3.12 -m unittest discover -s tests -v
```

Для этой версии ожидается 3 тестов и итог `OK`.
Тесты выполняются без создания окна. Они проверяют поведение,
а ручная демонстрация дополнительно показывает интерфейс.

## Проверка оформления

Один раз подготовьте отдельное окружение для инструментов проверки:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
```

Запуск проверки оформления и тестов:

```sh
.venv/bin/python scripts/check_quality.py &&
.venv/bin/python -m unittest discover -s tests -v &&
sh -n run.sh &&
(for script in scripts/*.sh; do
  [ -f "$script" ] || continue
  sh -n "$script" || exit 1
done)
```

Radon и Ruff нужны лишь для проверки, не для запуска эмулятора.
Проверяются применимые правила задания: структура, история коммитов,
отсутствие служебных и двоичных файлов, длина строк и функций, число
аргументов, docstrings, сложность, имена и литералы в сравнениях.
GitHub Actions выполняет проверку оформления, тесты и синтаксис `.sh`.

## Переход к ветке этапа и возврат

Открытие ветки на GitHub не переключает локальные файлы.
Перед переключением убедитесь, что `git status --short` не выводит
изменённых файлов. Для этапа 1 выполните в настоящем терминале:

```sh
git fetch origin
git switch stage-1
python3.12 -m unittest discover -s tests -v
```

Если локальной ветки ещё нет, Git создаст её из `origin/stage-1`.
После демонстрации вернитесь к полной версии:

```sh
git switch main
```
